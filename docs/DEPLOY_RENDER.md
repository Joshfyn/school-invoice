# Deploy to Render (Live Dev / Staging)

This guide deploys the **school-invoice API** to Render for **live dev** (not production).
Database: **Neon** (free Postgres). Cache: **Upstash** (free Redis).

---

## What’s already prepared in this repo

- `Dockerfile` — builds the API, includes `migrate`, runs migrations on startup
- `scripts/docker-entrypoint.sh` — `migrate up` then starts the server
- `render.yaml` — Render Blueprint (optional one-click setup)
- `.github/workflows/ci.yml` — tests + Docker build on push/PR
- `ENV=staging` — release-mode Gin, info logging (good for live dev)

---

## Step 1 — Push code to GitHub

If the repo isn’t on GitHub yet:

```bash
git add .
git commit -m "Prepare Render staging deployment"
git remote add origin git@github.com:YOUR_USER/school-invoice.git
git push -u origin main
```

**You are here:** do this first, then continue to Step 2.

---

## Step 2 — Create Neon PostgreSQL (free)

1. Go to [https://neon.tech](https://neon.tech) and sign up.
2. **New Project** → name it e.g. `school-invoice-staging`.
3. Copy the **connection string** (PostgreSQL).
4. Ensure it includes SSL, e.g.:
   ```
   postgres://user:pass@ep-xxx.region.aws.neon.tech/neondb?sslmode=require
   ```
5. Save this as `DATABASE_URL` — you’ll paste it into Render in Step 4.

No manual migration needed locally; the container runs `migrate up` on each deploy.

---

## Step 3 — Create Upstash Redis (free)

1. Go to [https://upstash.com](https://upstash.com) and sign up.
2. **Create database** → region close to your Render region (e.g. EU).
3. Copy the **Redis URL** (starts with `rediss://` or `redis://`).
4. Save as `REDIS_URL` for Render.

---

## Step 4 — Create Render web service

### Option A — Blueprint (recommended)

1. Go to [https://dashboard.render.com](https://dashboard.render.com).
2. **New → Blueprint** → connect your GitHub repo.
3. Render reads `render.yaml` and creates `school-invoice-api`.
4. When prompted, set **sync: false** variables:
   - `DATABASE_URL` → Neon connection string
   - `REDIS_URL` → Upstash URL
   - `PAYSTACK_SECRET_KEY` / `PAYSTACK_PUBLIC_KEY` → test keys for now
   - `TERMII_API_KEY` → optional for staging
   - `APP_URL` → `http://localhost:3000` until frontend exists
   - `API_URL` → leave blank for now; update after first deploy

`JWT_SECRET` can be auto-generated by the blueprint.

### Option B — Manual web service

1. **New → Web Service** → connect GitHub repo.
2. **Runtime:** Docker  
3. **Dockerfile path:** `./Dockerfile`  
4. **Plan:** Free  
5. **Health check path:** `/health`  
6. Add environment variables (see table below).

## Step 5 — Environment variables (Render dashboard)

| Variable | Example / notes |
|----------|-----------------|
| `ENV` | `staging` |
| `RUN_MIGRATIONS` | `true` |
| `DATABASE_URL` | Neon URL with `?sslmode=require` |
| `REDIS_URL` | Upstash Redis URL |
| `JWT_SECRET` | long random string (Render can generate) |
| `JWT_EXPIRY_HOURS` | `24` |
| `PAYSTACK_SECRET_KEY` | Paystack **test** secret key |
| `PAYSTACK_PUBLIC_KEY` | Paystack **test** public key |
| `TERMII_API_KEY` | optional in staging |
| `TERMII_SENDER_ID` | `SchoolInv` |
| `APP_URL` | frontend URL (localhost ok for now) |
| `API_URL` | `https://YOUR-SERVICE.onrender.com` (after first deploy) |

Render sets `PORT` automatically — the app already reads it.

## Step 6 — First deploy & verify

1. Trigger deploy (automatic on push, or **Manual Deploy** in Render).
2. Watch **Logs** — you should see:
   - `Running database migrations...`
   - `Starting API server...`
   - `Server starting on port ...`
3. Open:
   ```
   https://YOUR-SERVICE.onrender.com/health
   ```
   Expected JSON: `"status": "healthy"` (or `"degraded"` if Redis unreachable).
4. Update `API_URL` in Render env to your public URL and redeploy.

## Notes for live dev

- **Free tier cold starts:** Render free services sleep after ~15 min idle; first request may take 30–60s.
- **Migrations:** Run on every container start (`RUN_MIGRATIONS=true`). Set to `false` if you prefer manual migrations later.
- **Worker:** `Dockerfile.worker` is not deployed yet; add a second Render **Background Worker** when needed.
- **Production later:** use a paid Render plan, separate Neon branch, strong secrets, and `ENV=production`.

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Migrate fails on deploy | Check `DATABASE_URL`, SSL (`sslmode=require`), Neon IP allowlist (usually open) |
| Redis connection error | Use Upstash **Redis** URL; health may show `degraded` but API may still start |
| Build fails Go version | Dockerfile uses Go 1.23 — matches `go.mod` |
| 502 on health | Check logs; often DB/Redis URL wrong or service still starting |
